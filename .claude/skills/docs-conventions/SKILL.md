# Соглашения документации

README пишется на английском: сайт и репозиторий — портфолио, его читают работодатели. Пояснения для себя (заметки, планы) можно на русском в `docs/`. Код, команды, имена файлов не переводятся.

## Устройство

| Что | Где |
|---|---|
| Входная точка | `README.md`: название и одна фраза о проекте, скриншот, Live demo (если есть), Tech stack, Quick start, Project structure, ссылки на `docs/` |
| Отдельные страницы | `docs/<Name>.md` (PascalCase, английский) |
| Картинки для документации | `docs/images/<kebab-case>.png` — **не** `public/`: всё из `public/` публикуется на сайте |
| Картинки самого сайта | `public/images/` |

`docs/**` уже исключена из сборки Nuxt (`ignore` в `nuxt.config.ts`).

## README.md

1. **Порядок:** `# Название` → одна фраза → скриншот → разделы. Заголовки разделов — `##` (не `####`): по ним GitHub строит оглавление.
2. **Quick start** — команды, которые реально работают на чистой машине, в блоке `bash`, с нужной версией Node:
   ```bash
   npm ci
   npm run dev     # http://localhost:3000
   ```
3. **Tech stack** — версии из `package.json`, а не по памяти.
4. Если разделов больше 4 — оглавление `## Contents` со ссылками-якорями.
5. Новая страница в `docs/` — ссылка на неё в README.

## Ссылки

| Откуда → куда | Как |
|---|---|
| README / `docs/` → файл репозитория | **относительный** путь: `[nuxt.config.ts](nuxt.config.ts)`, `![…](docs/images/home.png)`. Работает в любой ветке и в форках |
| Внешняя ссылка на файл в репозитории (из другого репозитория, резюме) | `https://github.com/vadimlvov71/nuxt_vue/blob/main/<path>` — ветка `main` |
| Сайт локально | `http://localhost:3000` с пометкой «after `npm run dev`» |

Не использовать абсолютные `blob/...` ссылки на картинки внутри README: относительный путь надёжнее.

Якоря GitHub: строчные буквы, пробелы → `-`, знаки препинания удаляются. `## Quick start` → `#quick-start`, `## Tech stack` → `#tech-stack`.

## Картинки

```markdown
![Home page in dark theme: photo, skills and the list of git repositories](docs/images/home-page.png)
```

- Имя файла по содержанию, kebab-case (не `Nuxt.png`, не `image.png`).
- Alt-текст описывает, что видно; перед тем как писать alt — открыть картинку и посмотреть.
- Скриншот обрезать до нужной области; ширина до ~1400 px, PNG до ~300 KB.
- На скриншотах не должно быть токенов, личных данных сверх того, что и так есть на сайте.
- Схемы — Mermaid (блок ` ```mermaid `), GitHub отрисует сам.

## Проверка перед завершением

1. Все относительные ссылки ведут на существующие файлы:
   ```bash
   grep -oE '\]\([^)#:]+\)' README.md docs/*.md 2>/dev/null | sed -E 's/.*\]\(([^)]+)\)/\1/' | sort -u | while read -r f; do [ -e "$f" ] || echo "нет файла: $f"; done
   ```
2. Команды из Quick start выполнены и работают.
3. Версии в Tech stack совпадают с `package.json`.
4. После push открыть README на GitHub: картинки видны, якоря переходят.
